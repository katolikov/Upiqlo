Part 1  ·  The algorithm

The pipeline, stage by stage.

Five modules, four learned components, one scalar score — everything that follows is grounded in the real run_pipeline in engine/vendor/upiqal_cli.py. We’ll get to the desktop app once the algorithm is on the board.

Compare · 1 / 5

M1Normalization

load_image → tensor → normalize

Both images are loaded to (1, 3, H, W) float32 tensors in [0, 1], then resized so the longer side is at most max_side (default 1024) using Lanczos.

The pipeline then builds a multi-scale pyramid:

  • ref_full, tgt_full — native resolution, fed to the heuristics (Module 5) so 8×8 grid artefacts and edge-locked ringing aren't blurred away.
  • ref_tensor, tgt_tensor — downsampled to feature_side=256 for the feature branch. Matches the paper's "256 px minimum dimension" prescription.

Then Normalizer(mode="imagenet") applies VGG's ImageNet mean/std so Module 3's pretrained backbone sees what it was trained on.

Mismatched ref/tgt sizes? Downsample the larger; never upsample. Bilinear-up to ref-size was silently injecting blur into the target — a regression caught and fixed in T7.
Compare · 2 / 5

M2Chromatic transport

The ChromaticTransportEvaluator computes an Earth Mover's Distance between the local Oklab colour distributions of reference and target — patch by patch, 16-pixel windows, with 20 Sinkhorn iterations.

color_map = EMDoklab(ref, tgt) − EMDoklab(ref, ref)

The second term is the self-transport baseline. Sinkhorn-regularised EMD is non-zero even for identical distributions — subtracting ref→ref removes that bias so identical inputs yield a clean zero map.

Oklab is perceptually uniform; that's why the EMD lands closer to "looks different" than RGB-space distance would.

M3Deep statistics — A-DISTS over VGG16

The biggest box. A pretrained VGG16 walks both normalised images and at every stage returns three maps:

  • l(x,y) — luminance / first-order similarity (channel means).
  • s(x,y) — structure / texture similarity (channel covariances).
  • p_tex(x,y) — a learned texture-probability gate.
score = (1 − p_tex) · l + p_tex · s

So smooth regions weight the luminance term; textured regions weight the structure term — adaptive DISTS, paper- faithful. Maps are bilinearly upsampled to (H, W) and averaged across layers to produce deep_sim: high = visually similar.

Also yields residuals — per-layer feature differences fed straight into Module 4.

Compare · 4 / 5

M4Probabilistic uncertainty

global_anomaly_map.png

The ProbabilisticUncertaintyMapper consumes the VGG residuals and projects them through a learned block-diagonal Cholesky factor (weights/L_cholesky_blockdiag.pth).

anomaly(x,y) = ‖ L⊤ · residual(x,y) ‖²  →  Mahalanobis distance

Pixels where the residual lies outside the learned feature covariance light up. The output is upsampled to (H, W), normalised by per-sample peak (with a safe-divide guard for near-identical inputs), and saved as the global anomaly map — the catch-all "something's off here" channel.

Without trained weights, the mapper falls back to identity diagonal. Anomalies still localise, just less sharply.

M5Spatial heuristics

The only module that runs on the full-resolution pixels (Phase 1 of the paper) — JPEG blocks and ringing live at native scale.

Gibbs ringing Gaussian noise Blur / detail loss Color shift Anomaly (M4) Structure (M3)
  • JPEG blocking — DCT grid energy at the 8-pixel phase.
  • Ringing — wavelet-domain energy near strong edges.
  • Noise — wavelet residual standard deviation.
  • Blur — edge-spread function width.

Masks are then downsampled to the pipeline resolution and merged into the 7-channel diagnostic tensor.

Aggregation

Turning maps into a number.

Once every map is in hand the pipeline collapses them into one spatial score and then into a single [0, 1] scalar. Default ("sigmoid") mode:

score_spatial = 0.5 · deep_sim − 0.3 · anomaly_norm − 0.1 · color_norm
final = σ( 10 · ( mean(score_spatial) − 0.2 ) − 0.1 · heur_penalty )
  • w_structure = 0.5 — the deep similarity is the trunk; everything else trims it.
  • w_anomaly = 0.3, w_color = 0.1 — penalise unusual regions and chromatic drift.
  • heur_penalty — fraction of pixels flagged by blocking + ringing masks.
  • score_scale = 10, score_center = 0.2 — calibrated to spread the sigmoid across the realistic 0–1 score range.

An optional --score-mode nll swaps the sigmoid for the paper's negative-log-likelihood mapping:

final = exp( − 10 · total_nll )

Both modes share the same building blocks; the toggle is exposed as a per-session preference so power users can A/B them on the same pair.

Render

The unified diagnostic overlay.

The five severity masks plus M3-derived "structure damage" and M4 anomaly are stacked, argmax'd per pixel, then blended at alpha · severity over the target. One glance = which artefact dominates which region.

Per-pixel dominant

Whichever channel is strongest at this pixel wins the colour. Ties resolve to anomaly (the "main" layer).

Threshold gate

Pixels whose max severity ≤ 0.05 pass through to the target unchanged — clean regions stay clean.

Structure polarity flip

M3's deep_sim means "higher = more similar" — the inverse of every other channel. Composite paints magenta only where deep_sim is in the top 5 % of damage.

Anomaly · primary Structure Ringing Noise Color shift Blur

Colours validated against Coblis / Sim Daltonism for protanopia and deuteranopia — every artefact class is perceptually distinct even with red-green colour vision deficiencies.

Part 2 · The application

Beyond Compare for image quality.

Drop in a reference and a target. Upiqal renders both alongside a third pane that switches between seven diagnostic layers — anomaly, structure, color, ringing, noise, blur, plus a unified overlay — and writes back a single 0–1 quality score with the dominant artefact named in plain English.

100 % offline

0 hops

No Python install, no pip-at-runtime, no background web server. The full VGG16 ships inside the installer.

Native shell

Tauri 2

macOS · Windows · Linux. Browser-like tabs, 3-pane workspace, synchronized zoom & pan.

True cancellation

≲ 1 s

Cancel SIGKILLs the inference subprocess. CPU and torch memory return to the OS instantly.

Architecture

Three processes, one window.

Tauri 2 host · Rust
src-tauri/ · owns the native window, spawns the sidecar, holds engine port + token
Python engine · FastAPI
engine/ · loopback only · bearer-token auth · per-request subprocess
⇄ HTTP / SSE ⇄
React UI · Vite · Tailwind · Zustand
ui/ · rendered in the Tauri webview · streams progress, draws heatmaps

The webview never reaches the public internet. Every byte that crosses between UI and engine moves over 127.0.0.1 with a per-launch bearer token only Tauri knows.

Boot sequence

How Tauri trusts the engine.

  • Tauri host spawns the PyInstaller sidecar binary.
  • Engine opens socket(0) — OS picks a free port.
  • Engine prints two stdout lines, then nothing else:
UPIQAL_ENGINE_PORT=51017
UPIQAL_ENGINE_TOKEN=<128-bit secret>
  • Rust host parses both, hides the rest of stdout behind [engine] in the log.
  • UI calls invoke("get_engine_port") / get_engine_token via Tauri IPC.
  • Every /api/* call carries Authorization: Bearer <token>. SSE uses ?token= because EventSource can't set custom headers.

Why not a well-known port?

Multiple windows collide. AV on Windows occasionally blocks fixed high ports. socket(0) is deterministic — the OS gives a known-free port, every time.

Why a per-launch token?

Defence in depth. Even if a process on the same machine guessed the port, it can't talk to the engine without the secret that only Tauri's parent process saw.

Stage 01 · Boot

01Launch & handshake

The Tauri host's job during boot is small but load-bearing: spawn the sidecar, parse the two handshake lines, expose them to the webview, and from then on stay out of the way.

  • Sidecar binary is bundled per platform — upiqal-engine-<triple>.
  • Engine logs both lines to stdout exactly once. Anything after that is routed to the Rust log.
  • UI polls GET /healthz every 5 s — the top-right chip turns green when algorithm_available: true.

Each tab is an isolated session — its own reference path, target path, parameter snapshot, layer selection, annotations, and cached result. Two modes:

Single — A vs B

Two files, one compare. The fastest path from "is this the same image?" to a number.

Folder — paired sweep

Two directories. The engine pairs by filename (or by index), Prev / Next jumps between pairs, results cache per-pair so you can move back and forth without re-running.

Per-session parameter snapshots mean changing max_side on Tab 2 won't blow away Tab 1's cached run.

Stage 03 · Compare

03Compare — the headline stage

The Compare button kicks off the FR-IQA pipeline. The engine spawns a fresh Python child (upiqal_engine.subworker), feeds it ref+target+params, and tails its stdout for stage events.

3 / 5 · Deep Statistics

Subprocess isolation

Each Compare is its own OS process — torch allocator arenas can be released with a single process.kill().

Streaming progress

Upstream prints [N/M] Stage … done; the engine parses, the UI renders each event as a smooth interpolation.

Result caching

LRU keyed by (hash(ref), hash(tgt), params). Same input again = instant repaint, no model reload.

Stage 04 · Streaming & cancel

04Server-Sent Events & true cancellation

The UI opens POST /api/compare-paths/stream and reads SSE events as they arrive:

14:32:01 open token=ub31…
14:32:01 stage 1/5 Normalization
14:32:01 stage 2/5 Chromatic Transport
14:32:01 stage 3/5 Deep Statistics
14:32:03 stage 4/5 Uncertainty Mapping
14:32:03 stage 5/5 Spatial Heuristics
14:32:03 result score=0.642 dominant=Blur
14:32:03 done

Cancel really cancels.

Hit Cancel and the UI fires DELETE /api/compare/<token>. The engine looks up the subworker process and calls process.kill() → SIGKILL → torch tensors, allocator arenas, model buffers — all reclaimed by the kernel within ≲ 1 second. No "result still goes to cache anyway." No lingering CPU.

The non-streaming endpoints run in-process for cheap calls (cache hits, single quick pairs). Streaming + cancellation is reserved for the heavy path.
